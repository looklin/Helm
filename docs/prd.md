# PRD：工业 HMI 与 PLC 读写平台

## 1. 产品概述

### 1.1 产品名称

Helm HMI Platform

### 1.2 产品目标

打造一个可替代传统 Pro-face 类 HMI 软件的本地化工业操作平台，在工控机上完成一体部署，提供 PLC 实时监控、参数读写、报警管理、趋势展示、配方下发和审计追溯能力，并支持 iPad、手机、PC 在局域网内访问。

### 1.3 目标用户

- 产线操作员
- 设备调试工程师
- 电气 / 自动化工程师
- 班组长 / 现场管理人员
- 设备维保人员

## 2. 业务背景与机会

传统 HMI 工具存在以下问题：

- 页面开发效率低，迭代和版本管理不友好。
- 移动端支持差，通常只能在触摸屏或指定终端上操作。
- 报警、趋势、配方、权限、审计往往分散或能力不足。
- 与现代 Web 系统和企业 IT 环境集成成本高。

本项目通过 Node + React + SQLite 的本地一体化方案，把工控现场操作界面做成标准 Web 应用，从而同时覆盖工控机本机、平板和手机。

## 4. 核心使用场景

### 场景 1：工控机本机操作

操作员在工控机触摸屏上打开 HMI 页面，查看设备状态、启动 / 停止设备、调整工艺参数并查看报警。

### 场景 2：iPad 巡检

工程师携带 iPad 接入现场无线路由器，在车间内浏览设备状态、处理报警、查看趋势曲线和修改授权参数。

### 场景 3：手机应急处理

班组长使用手机访问系统，快速确认报警、查看当前设备状态、执行低风险参数调整。

### 场景 4：配方下发与追溯

工程师选择某个产品配方，一键下发到 PLC，并核对回读值。所有动作被记录，便于问题追溯。

## 5. 功能需求

### 5.1 用户与权限

- 支持本地账号登录
- 支持角色权限模型
- 支持按页面、按点位、按操作类型授权
- 高风险操作支持二次确认
- 支持自动登出和会话超时

### 5.2 PLC 连接管理

- 支持配置多个 PLC 连接
- 支持不同协议驱动
- 支持连接状态监控
- 支持断线重连和状态告警
- 支持分组轮询与点位缓存

### 5.3 点位管理

- 支持点位增删改查
- 支持数据类型、缩放、单位、权限、采样周期设置
- 支持点位分组
- 支持批量导入导出

### 5.4 实时监控与控制

- 支持数字量、模拟量、文本量显示
- 支持按钮、切换、输入框、滑条等控制组件
- 支持联锁提示与危险操作确认
- 支持实时状态推送

### 5.5 报警管理

- 支持报警规则配置
- 支持实时报警列表
- 支持确认、消警、查询历史
- 支持按设备、时间、级别过滤

### 5.6 趋势与历史

- 支持当前趋势和历史趋势
- 支持多曲线对比
- 支持时间范围查询
- 支持导出 CSV

### 5.7 配方管理

- 支持配方模板管理
- 支持版本化
- 支持配方下发
- 支持回读校验
- 支持下发审计

### 5.8 审计与日志

- 所有写操作记录操作人、时间、对象、旧值、新值、结果
- 支持登录日志与异常日志
- 支持日志查询与导出

### 5.9 系统管理

- 支持数据库备份与恢复
- 支持系统参数管理
- 支持运行健康检查
- 支持查看服务版本与驱动状态

## 6. 非功能需求

### 6.1 性能

- 单台工控机支持 1 到 5 个 PLC 并发连接
- 支持 500 到 3000 个点位轮询
- 关键页面首屏加载时间小于 3 秒
- 实时数据显示延迟目标小于 500ms

### 6.2 可用性

- 系统支持断线重连
- 前端在后端不可达时给出清晰降级提示
- PLC 异常不应导致 Web 服务整体崩溃

### 6.3 安全性

- 支持账号鉴权与角色权限
- 支持写操作审计
- 支持可选 HTTPS
- 支持局域网白名单或网段限制

### 6.4 可维护性

- 前后端与 PLC 驱动解耦
- 所有接口和点位模型强类型化
- 支持后续扩展更多 PLC 协议

## 8. 技术方案决策

### 决策 1：Web HMI 而不是原生客户端

原因：

- 同时适配工控机触摸屏、iPad、手机和 PC
- 维护成本低
- 页面发布和迭代速度快

### 决策 2：SQLite 而不是独立数据库服务

原因：

- 更符合工控机本地单机部署
- 安装和备份简单
- 降低运维复杂度

### 决策 3：Fastify + React + TypeScript

原因：

- 性能、开发效率和长期维护平衡较好
- 适合高频实时数据和长期迭代

## 10. 风险与应对

### 风险 1：不同 PLC 协议差异大

应对：

- 先确定首批支持品牌
- 做统一驱动接口层
- 以“点位模型 + 驱动适配器”方式隔离差异

### 风险 2：移动端误操作风险

应对：

- 细化权限
- 高风险操作二次确认
- 对关键写入加入审批或口令

### 风险 3：SQLite 历史数据膨胀

应对：

- 当前值与历史值分表
- 历史数据归档和保留策略
- 趋势数据可按分钟 / 秒级降采样

### 风险 4：现场网络不稳定

应对：

- 本地工控机作为唯一控制中心
- 移动端只作为浏览和授权控制入口
- 页面明确显示在线状态

## 11. 成功指标

- 工控机可稳定连续运行 30 天以上
- 移动端在局域网内可稳定访问
- PLC 实时读写满足现场使用要求
- 操作审计覆盖率 100%
- 能替代现有至少一条产线的基础 HMI 功能

## 12. 下一步建议

1. 先确定首批 PLC 品牌、协议和点位规模。
2. 先做单设备 MVP，不要一开始做成全厂级平台。
3. 优先把“实时读写 + 权限 + 审计 + 报警”做稳，再扩展趋势和配方。
